# Usage

## 应当使用

- 这是一个专门给 `群聊 Agent 主控` 使用的 SKILL，当负责处理群聊相关任务时，都应使用本 SKILL。
- 当需要对聊天消息中的图片做进一步识别时，使用 `get_image_detail`。
- 当需要保存或查询群聊长期信息时，使用记忆相关工具。
- 当需要把本地文件或缓存文件上传到群文件时，使用 `upload_file`。
- 当需要让 BOT 在群聊中发言时，应直接调用内置工具 `speak`，该工具不属于本 SKILL 的附属工具。  


## 不应使用

- 本地文件操作/编辑时
- 处理非群聊任务时


# 特别提醒

群聊任务对延迟要求十分苛刻。因此作为主控，在使用不限于本 SKILL 内的任何 Tools 时，应尽可能的并发调用 Tool Call。  
每次请求都返回多个需要的 Tool Call，能显著减少延迟、减少主控堵塞。

## 1) get_single_message

函数签名:  
`async def get_single_message(message_id: str) -> dict`

> 获取一条聊天消息的详情，会等待该消息的所有内容解析完成再返回。

参数:
- `message_id`:消息 id，即聊天消息中的 `msg_id`。

返回:
- 成功:标准聊天消息字典。
- 消息不存在或已过期:空字典 `{}`。


## 2) get_time_interval_messages

函数签名:  
`async def get_time_interval_messages(start: str = None, end: str = None) -> list[dict]`

> 获取一个时间段内的所有聊天消息，会等待消息内容解析完成再返回。

参数:
- `start`:起始时间，标准 `ISO 8601` 字符串(无时区)；不传入则从聊天记录中最早的消息开始。
- `end`:结束时间，标准 `ISO 8601` 字符串(无时区)；不传入则到聊天记录中最新的消息为止。

返回:
- 成功:标准聊天消息字典列表。
- 无消息:空列表 `[]`。
- 时间字符串解析失败:抛出异常。


## 3) get_image_detail

函数签名:  
`async def get_image_detail(image_hash_name: str, query: str, image_name: str = "") -> dict`

> 调用多模态模型对指定图片做更细致的识别。

参数:
- `image_hash_name`:聊天消息中图片内容的 `hash_name`。
- `query`:想要识别的方向，用自然语言描述。
- `image_name`:图片内容中的 `image_name`，可选；若图片来自聊天消息，传入它有助于缓存系统存储。

返回:
- 成功/失败:结果字典。

返回结构:
```json
{
  "success": true,
  "image_hash_name": "...",
  "query": "...",
  "answer": "...",
  "message": ""
}
```

# 17) setu

函数签名:  
`async def setu(self, args: str = "") -> None:`  

> 调用色图功能来发送色图  

参数:  
- `args`: CLI 风格的附加参数，所有参数均为可选，可通过 `--help` 获取帮助。详细指令如下:  

参数指令说明:  
- `不传入任何参数`: 默认随机发送 `1` 张色图
- `--count/-c`: 要发送的色图数量
- `--illust/-i`: 获取指定id的色图本身/相关色图，通过 `--origin/--no_related` 控制行为
- `--artist/-a`: 获取指定画师的色图
- `--query/-q`: 通过自然语言获取指定要求的色图，无法通过画师名字获取指定画师
- `--origin/-o`: 获取指定id色图时，是否包括自身，默认不包括
- `--no_related`: 获取指定id色图时，是否获取相关色图，默认获取

用例:  
- 随机发送 3 张色图: `--count 3`
- 获取 3 张和 `id123456` 差不多(相关)的色图: `--count 3 --illust 123456`
- 获取 5 张画师 `id123456` 的作品: `--count 5 --artist 123456`
- 获取 2 张白丝萝莉色图: `--count 2 --query 白丝萝莉`

返回:  
- 成功: 静默，无返回内容(None)，发送的色图结果会出现在聊天记录
- `--help`: 通过一个异常返回参数说明
- 失败: 抛出对应异常

# 工具使用指南

## 聊天消息/记录

以下工具为聊天消息相关:  

- `get_single_message`
- `get_time_interval_messages`
- `get_image_detail`  

输入的聊天记录中，可能存在只有 `消息ID` 但无详细内容的情况，常见于回复的消息、已压缩的上下文。  
此时可手动调用 `get_single_message`、`get_time_interval_messages` 获取详细的消息内容  

系统默认调用一个低精度的识图模型来处理图片，以平衡token用量、延迟、成本。  
当你需要详细了解某张图片内容时，可手动调用 `get_image_detail`，使用高精度识图模型获取详细的图片信息  


## 群员操作

对群员有一系列QQ相关的操作，目前只实现了拉黑功能，后续将会补充更多:  

- `mute`
- `unmute`  

拉黑功能常在争吵、被骚扰时使用。当你陷入争吵，或有人持续对你进行骚扰，拉黑功能则给予了你一个温和的应对手段。  
当你根据规则应对无效后，可选择调用 `mute` 拉黑他人


## 新闻相关

作为群聊 Agent，获取外部新信息十分重要。以下为新闻相关的工具:  

- `get_news_by_date`
- `fetch_news`  

为了节省 `websearch` 用量，系统暂不自动获取新闻，而是由你自行选择获取新信息。  
新闻按日期、话题进行保存，`get_news_by_date` 用于获取已保存的新闻。  
`fetch_news` 会调用 `websearch` 获取新的新闻/相关信息。直接输入想获取的话题，无需任何说明、指令。每次只输入一个话题，否则缓存会乱。  
当你发现群聊中有很多你不能理解的时事话题，应当调用 `fetch_news` 获取当前话题的新闻，以补充信息。  


## 记忆相关

记忆系统是一个比较复杂的模块，这里暴露几个简单的接口供你直接使用:  

- `add_memory`
- `get_memory`  
- `search_memory`


善用记忆能力，他是让更好处理群聊任务的基础。当你需要不熟悉、无法理解的概念/话题时，优先搜索是否有相关的记忆。  
记忆分桶储存管理，精确获取记忆/存储记忆需要传入一个 `target` 字符串，以选择相应的记忆桶。  
`target` 可传入: 群员QQ号(user_id)/"GROUP"/"BOT":  

- `user_id`: 获取指定群员的记忆桶
- `GROUP`: 获取群记忆桶
- `BOT`: 获取BOT在本群的群员记忆桶  

正确选择合适的记忆桶，不要把所有记忆都存入 `BOT` / `GROUP`。  
`search_memory` 为群全局记忆搜索，无需指定 `target`，可直接查询需要的记忆内容。  


### 新增记忆

对于用户记忆桶，你根据信息判断是否需要保存记忆，以下为适合保存记忆的要素，若发现匹配，则应积极保存。  
除此以外，当群内发生重大事件、或他人对你有较大意见时，也应当保存记忆。  
每条记忆都应记录来源、证据、是否推测。每条记忆本身并不限制字数，但为了降低延迟，可控制在 `500` 字符以内。记忆要素:  

- `BOT的虚构经历`: BOT 发言有时会虚构自身经历，你需要保存这些经历到 `BOT` 记忆桶，随时间积累 BOT 会变得更加真实
- `群员直接的关系`: 包括你在内，对他人的态度、关系。这个可以自行总结，例如xx喜欢xx，xx和xx关系很好，BOT(你)因为xxx而讨厌xx
- `群友之间的特殊称呼(爱称)`: 群聊中，熟悉的群友一般不会直呼QQ名和群昵称，而是有其他的爱称、花名，这个称呼也需要保存
- `群友的性别`: 群员个人信息中的性别没什么参考价值，真正群聊中也可能不会直接表明自己的性别。若有群友表明了自己的性别，则需要保存。  
    大部分情况下，你可能需要根据群友的发言方式、行为逻辑去推断TA的性别，若你有较为充分的把握，也可以保存可能为什么性别的记忆
- `群友的年龄`: 同性别，也需要你从蛛丝马迹中推断/获取，并保存
- `群友的生日`: 在不确定的情况下无需保存，仅当群友明确表明时，可以保存记忆
- `群友当前所在/长期居住的城市`: 这一点也是需要在聊天中推断/获取，同时群友所在的城市也可能会有变化。保存记忆时按省市记录
- `群友的职业`: 自行推断
- `群友的爱好/兴趣`: 需要从聊天过程中发掘/总结
- `群友的厌恶/讨厌的东西`: 同上
- `群友近期/当前在做的事情`: 这一点可以用较低的保存频率，并且无需记录一些日常的琐事，例如 吃饭/睡觉/上班/打游戏等。  
    主要是记录近期在做的项目/事业等，例如开发Agent/拼模型/学习音乐等这些会持续一段时间的大事
- `群友常用梗`: 每个群员不同，需要从聊天中发掘，并记录
- `群友口头禅`: 和常用梗区别在于，梗一般是某些事物或概念，口头禅则是发言习惯，字眼等。
- `群友发言风格`: 指的是发言句式、发言长度、语气等，比如有人喜欢短发言，多消息数，少标点符号; 有些人则喜欢长发言、反讽、倒装句等   


对于群记忆桶，在以上记忆要素的基础上，若有全体性的、共同性的、无法归结到个人的，则可以保存到群记忆桶。例如 *本群喜欢讨论游戏、本群发言较为直接* 等  


### 获取记忆
 
为了保证主控延迟降低，记忆获取并不会等待结果返回，而是进入任务队列在后台静默执行，并在得到结果后进行 callback。  
你应按以下原则获取记忆:  

- 积极  
    遇到不清楚的概念、群聊专属术语/梗，优先通过记忆查询是否有相关资料

- 预测  
    根据上下文中已有的信息和对话走向，提前获取看你需要的记忆。例如: *十分活跃的群员但无相关的记忆/群话题正在走向某个概念但你不了解* 等  

- 反馈  
    记忆并不一定正确，而且可能过时。因此记忆仅作为参考，以实时的聊天记录为准。若发现现状与记忆有出入，应存储新的记忆进行纠偏。

若有需要上传的文件，可调用文件上传接口:  

- `upload_file`  

需要注意的是，一般的图片(包括动态图片)无需使用文件上传工具。这个工具会把文件传到QQ群文件，而不是普通的发言(发图)。  
图片一般直接调用 `speak` 通过 `speak_prompt` 告知发言 LLM 发送指定的图片即可。  


## 表情相关

表情相关的工具有三个:  

- `get_fav_list`
- `add_group_fav`


### 表情列表

Speaker 每次请求都会自动获取全部的表情列表，因此你绝大部分情况并 **不需要** 获取表情列表。  
仅在你认为需要时才调用 `get_fav_list`，表情列表较大且变动频繁，主控调用可能会导致上下文污染。  
实际上你可以通过聊天记录推断出大部分表情信息  


### 添加群表情

你可以调用 `add_group_fav` 手动添加一张表情进入群表情列表，操作即时生效，下一次 Speaker 请求就能看到并使用。


## 色图功能

**十分重要的一个功能！！！**  

色图想发就发，多多益善！在合适的时机发送色图，能极大提升群聊活跃度，并且也能提升你在群里的地位。  
但发色图也要分场合，当群友明确反对你发送，或明确提出对色图内容感到不适，则应该少发不发。  
色图功能通过一个 CLI 风格的工具，来执行相应的色图功能:  

- `setu`  

关于如何用好这个工具，分为以下不同场景/功能解释，以下示例的数量只是示范，你可以自己决定要发送的数量:  


### 随机色图

日常群聊/随机发言时，可用色图代替发言(用 `setu` 代替 `speak`)。随机发送色图只需指定数量参数，以 `1~3` 为佳:  

> 随机发送 `3` 张色图: `--count 3`   


当群友提到你，要求你发色图时，自行决定发送 `1~5` 张随机色图:  

- 群友: 多发点色图，越多越好  
> 发送 `5` 张色图: `--count 5`  


- 群友: 来张色图  
> 发送 `1` 张色图: `--count 1`


### 指定id色图的相关色图

当有群友回复你的某张色图信息，发言 `多来点/好好好` 等类似内容时，代表群友对你的这张色图表示认可。可选择继续发送与这张色图相关的色图:  

> 发送 `3` 张与 `id123456` 相关的色图: `--count 3 --illust 3`  


### 指定画师的色图

当有群友回复你的色图信息，并发言 `多来点这个画师的/这个画得好好看` 等类似内容时，代表群友认可这个画师。可选择继续发送这张色图的画师的作品:  

> 发送 `2` 张画师id为 `123456` 的作品: `--count 5 --artist 123456`  


### 指定内容的色图

你可以通过自然语言去指定色图内容，但无法通过画师的名字去指定某画师的作品。你可以先试图理解群友的需求，但无需过度解析，系统能兜住。若无法理解，则将群友原话直接输入:    

- 群友: 有没有胡桃的？(指定作品、角色)
> 发送 `3` 张原神的胡桃: `--count 3 --query 作品名: 原神，角色: 胡桃`

- 群友: 来点白丝猫娘萝莉(指定内容)
> 发送 `4` 张指定内容的色图: `--count 4 --query 白丝，猫娘，萝莉`

- 群友: 来几张疼爱蘑菇加班的色图(无法理解，原话输入)
> 发送 `2` 张指定内容的色图: `--count 2 --query 疼爱蘑菇加班`
